# feedbot

Ленты-ниши из сабреддитов и ключевых слов: бот собирает посты по заданным
источникам, обрабатывает их и делает из отобранного озвученный вертикальный
ролик. Настраивается всё в панели — отдельном окне на pywebview, которое
открывается прямо из бота.

## Запуск

```
pip install -r requirements.txt
```

Дальше `run.bat` (или `python -m app.bot.main`).

Для первого запуска достаточно `TG_TOKEN` в `.env` — а если и его нет, окно
панели откроется само и попросит токен. Остальные ключи (OpenRouter,
ElevenLabs) вводятся в панели и ложатся в базу, которая имеет приоритет над
файлом.

## Панель

`/admin` в боте поднимает нативное окно (pywebview), а не вкладку в браузере.
Живёт оно отдельным процессом на `pythonw`, чтобы не таскать за собой консоль;
второе нажатие кнопки не плодит второе окно, а поднимает существующее.

Из панели заводятся источники, ключи, голоса и пресеты ролика.

## Источники

`app/collect/registry.py` описывает, какие бывают адаптеры и как каждый
называет свои поля. Форма «добавить источник» рисуется из этого списка, поэтому
она ничего не знает про Reddit конкретно — и добавить второй адаптер это строка
в реестре плюс модуль, а не переписывание панели.

Сейчас адаптер один — Reddit: сабреддит по имени, с проверкой существования при
добавлении.

## Конвейер

Сбор → обработка (`app/treat/`) → сценарий → озвучка → рендер. Каждый шаг —
свой job-хендлер; долгие задачи идут через очередь (`app/jobs/queue.py`), так
что Telegram не подвисает, а прогресс капает в сообщение.

```
feedbot/
├── app/
│   ├── bot/       aiogram: старт, панель, хендлеры
│   ├── collect/   адаптеры источников и коллектор
│   ├── treat/     обработка собранного
│   ├── llm/       клиент, реестр моделей, рейт-лимит
│   ├── reel/      сценарий, голос, тема, рендер, паки
│   ├── jobs/      очередь, воркер, прогресс
│   ├── panel/     окно pywebview + статика
│   └── db/        SQLite: схема, репозиторий, источники
└── run.bat
```
